# 調査: 表示の色・透明度・同じ座標のゾーン・重なる接続(ビジュアライズの改善の前)

- 日付: 2026-10-22
- 依頼: 色の扱いがどうなっているか、透明度のパラメータが使えるか、同じ座標にあるゾーンの扱い、接続が重なるときの描き方
- 対象: `droneflow/visualization/palette.py`・`graphical_view.py`・`terminal_view.py`、`droneflow/parsing/line_tokenizer.py`
- 確かめ方: コードを読み、検証用のマップ `_tmp/visual_review/overlap_demo.txt`(a と b が同じ座標 (2,0)、a の色が `#ff000080`、
  s-c と b-g が他のゾーンの上を通る)をヘッドレス(`SDL_VIDEODRIVER=dummy`)で描いて `_tmp/visual_review/overlap_t1.png` に保存した。
  配布マップの見た目は `_tmp/visual_review/*.png`(課題の例・challenger・ultimate_challenge・50×50 のメッシュ)。

## 1. 色の扱い

- パーサー: `color=` は任意の1語の文字列をそのまま `Zone.color` に入れる(課題 VII.4「任意の1語、固定のリストなし」)。検査しない。
  行頭が `#` の行だけがコメントなので、`[color=#ff000080]` のような値もそのまま通る。
- `palette.py`: 色名 → RGB の表(25語。配布マップの色を `rainbow` 以外すべて含む)。大文字小文字は区別しない。
- ターミナル表示: 表にある名前だけを 24bit ANSI で塗る。表にない名前・`#...`・色なしは端末の既定色。`NO_COLOR` または端末でない出力先では色を出さない。
- グラフィカル表示(`zone_rgb`): 表 → なければ `pygame.Color(名前)`(CSS/X11 の色名と `#RRGGBB`・`#RRGGBBAA`)→ それもなければ灰色 `(170,170,170)`。
  ゾーンの塗りに使うだけで、ドローン・接続・枠の色は固定(blocked は色に関係なく濃い灰色)。

## 2. 透明度

- **使えない**。`zone_rgb` は `RGB`(3つ組)を返し、`pygame.Color("#ff000080")` のアルファ(128)を捨てる。
  描画は画面のサーフェスへの `pygame.draw` 直接で、アルファは効かない(使うには `SRCALPHA` のサーフェスに描いて `blit` する必要がある)。
- ターミナルには透明度の概念がない。`#...` の形はそもそも色として扱われない(既定色)。
- 課題は色の書式を定めていない(1語ならよい)ので、透明度を使うかどうかは表示側の設計判断になる。

## 3. 同じ座標のゾーン

- パーサー: 座標の重複は検査しない(課題は「名前が一意」「座標は整数」だけを求める)。
- グラフィカル: `_Layout` は名前ごとに同じピクセルを返すので、**後に宣言したゾーンが前のゾーンを完全に隠す**(デモでは a が b の下に隠れた)。
  - 名前・`0/2` と `1/2` の数字が同じ位置に重ね書きされて読めない。
  - ドローンは描く位置(ピクセル)ごとにまとめるので、a と b にいる機が1つのかたまりになる。
  - マウスを乗せたときの詳細(`zone_at`)は宣言が先のゾーン(a)だけを返し、見えているゾーン(b)と食い違う。
  - a-b の接続があれば長さ0の線になり見えない。
  - 最近接距離(`_closest_distance`)は重複を除いて計算するので、ゾーンの大きさには影響しない。
- ターミナル: ゾーンは名前で一覧するので、座標の重複の影響はない。

## 4. 接続が重なるとき

- 描き方: 接続はすべて両端のゾーンの中心を結ぶ直線で、宣言順に描く。太さは `1 + min(max_link_capacity, 4)`、色は飛行中の機がいれば明るい灰色、
  そのほかは灰色(同じ色)。容量が2以上なら中点に `x<容量>` を書く。その後、そのターンに動いた機の軌跡(黄色・太さ3)を上に重ね、最後にゾーンを描く。
- そのため:
  - **他のゾーンの上を通る接続は、そのゾーンに隠れて「2本の接続」に見える**(デモの s-c は b の下を通り、s-b・b-c と区別できない。b-g も c の下を通る)。
  - 同じ直線上に重なる接続は、後に描いたものしか見えない(色も同じなので区別できない)。
  - 中点の `x2` がゾーンの下に隠れることがある(デモの s-c の中点は b と同じ位置)。
  - 交差する接続は単に交差して描かれる(交点に意味はない)。
  - 軌跡は直線なので、隠れた接続を通った移動も、隣の接続を通ったように見える。
- ターミナル: 接続そのものは描かない(飛行中の機だけ `D2 hub-roof1 -> roof1` と接続名で出す)ので、重なりの問題はない。

## 改善の候補(未決。ユーザー判断待ち)

1. 同じ座標のゾーンを少しずらして並べる(重なったゾーンを円周上に配置するなど)。または重なりを1つの印にまとめて、詳細はマウスで見せる。
2. 他のゾーンの上を通る接続・重なる接続を曲線(弧)にして区別する。
3. 透明度に対応する(`#RRGGBBAA` を受け付け、ゾーンを `SRCALPHA` のサーフェスに描く)。重なったゾーンが透けて見える効果もある。
4. 中点のラベル(`x2`)をゾーンと重ならない位置に置く。
