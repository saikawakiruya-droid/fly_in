# テスト設計: グラフィカル表示の速さのキー(0〜60 秒)

- 日付: 2026-10-23
- フェーズ: テスト設計(作成は `test/delay_keys_range`)
- 対象: `droneflow/visualization/graphical_view.py` の `faster`・`slower` と、キー操作(VG11)
- 参照したバグ記録: `docs/bugs.md` 2026-10-22「グラフィカル表示の速さのキーが、`--delay` の範囲の端で逆に働く」

## 既存テストの変更

| ID | 理由 | 変更 |
|---|---|---|
| VG11 | 上限が 5 秒から 60 秒に、0.05 秒を下回ると 0 になった | (1.0, ↓×4) は 16.0、(0.1, ↑×3) は 0.0。ほかは同じ。docstring の「within 0.05 and 5 seconds」を直す |

## 追加(pygame の窓は開かない。関数を直接呼ぶ)

| ID | 何を確かめるか | 入力 | 期待 |
|---|---|---|---|
| DK01 | 速くは半分 | `faster(1.0)`、`faster(0.1)` | 0.5、0.05 |
| DK02 | 0.05 秒を下回ると 0 | `faster(0.05)`、`faster(0.08)` | 0.0、0.0 |
| DK03 | 0 は 0 のまま(遅くしない) | `faster(0.0)` | 0.0 |
| DK04 | 遅くは2倍 | `slower(0.5)` | 1.0 |
| DK05 | 0 からは 0.05 秒 | `slower(0.0)`、`slower(0.01)` | 0.05、0.05 |
| DK06 | 上限 60 秒(速くしない) | `slower(40.0)`、`slower(60.0)` | 60.0、60.0 |
| DK07 | どちらも逆向きに働かない | 0〜60 の代表値(0, 0.01, 0.05, 0.5, 5, 59, 60) | `faster(d) <= d`、`slower(d) >= d` |
