# 遠回りの一手を許す試作(台数の配分)

- 日付: 2026-10-20
- 対象: develop(927d2e4 以降)の `Scheduler`。リポジトリ外の使い捨てスクリプトで `Scheduler._decide` を差し替えて計測した(コードは変更していない)。
- ユーザーの方針: 「出て行ったドローンの台数と残り移動距離の合計より小さいコストになる経路には出してよい。逆流は防ぐ必要がある」

## 解釈(試作での規則)

1. 最短の一手(`next_hops`)を今までどおり先に試す(立ち退きなし → 立ち退きあり)。
2. どれも使えず待つことになるドローンだけ、遠回りの一手を試す。遠回りの一手 = 隣のゾーン v で
   - `dist(v) < dist(u)`(**逆流の防止**: end までの距離が真に減る所にしか行かない。戻る・横に流れる移動は無い)、かつ
   - `cost(v) + dist(v) > dist(u)`(最短ではない)。
3. 出してよい条件: `cost(v) + dist(v) < dist(u) + ahead(u)`(または `≤`)。
   - `ahead(u)` = 「出て行った台数」= u から最短経路で辿れる先のゾーン(または着陸先)にいて、まだ着いていないドローンの数。
   - 「start」版はターンの初めの位置で数え、「live」版は同じターンに先に判断した移動も数える。
4. 遠回りの候補は総コストの小さい順。立ち退きの使用の有無で2通り。

距離が毎回真に減るので、今のスケジューラの「必ず終わる・毎ターン少なくとも1機動く」という性質はそのまま保たれる。
立ち退きは、どこにいるドローンにも最短の一手だけを使うので、遠回りを混ぜても再帰は必ず終わる。
`TurnResolver` は「隣のゾーンか」しか見ないので、遠回りの一手もそのまま合法(全マップで `SimulationError` 0件)。

課題の例の5ターン(`≤`・live・立ち退きあり)のターンログでは、D2・D4 が roof1 経由、ほかが corridorA 経由。手で見積もった下限(最短3機+遠回り2機で5ターン)と一致。
