# 2026-11-10 渋滞しない経路の組を先に求める(最小費用流と、時間方向への繰り返し)

ユーザーの考え: 満員になる道では結局詰まり、ならない道では道を空けておく意味がない。欲しいのは常に渋滞せずに進めるルートで、
それがわかれば最短に収束するはず。

## 結論

- 考え方は正しく、スタートとゴールが1つずつのときに最適になる既知の方法がある:
  **最小費用流で「容量を守る経路の組と、各経路に毎ターン送る台数」を求め、それを毎ターン同じように繰り返す**
  (Ford–Fulkerson の temporally repeated flow。最早到着の quickest flow 問題)
- ただし「最短経路1本に収束する」のは台数が少ないときだけ。台数が多いと、遠回りでも並行して使う方が早く終わる。
  どこまで遠回りを使うかは次の式で決まる
- 2026-10-19 の `bottleneck-detection-options.md` で F(最小費用流)を「遠回りの配分の段階で再検討」としていた。その再検討にあたる

## 終了ターンの式

経路 i の長さ(ターン数)を l_i、毎ターン送れる台数を c_i とすると、経路を k 本使ったときの終了ターン T は、
次を満たす最小の T:

    Σ_i c_i × (T − l_i + 1) ≥ N   (T ≥ l_i の経路だけ足す)

最短の順に経路を足していき(successive shortest path)、T が縮まなくなったら止める。

## 地図への当てはめ(確認が要る点)

- ゾーンの容量: ゾーンを「入口→出口」の2点に分け、その間の辺の容量を max_drones にする(start・end は無制限)
- 接続の容量: 毎ターン出発できる台数 = max_link_capacity。restricted への接続も、到着ターンに空く規則
  (2026-10-23 の課題 v2)なので毎ターン c 台出発できる
- 長さ: 入るゾーンの turn_cost(normal・priority 1、restricted 2)。blocked は辺を作らない
- 残余グラフに負の辺が出るので、Bellman-Ford か、ポテンシャル付きダイクストラを使う
- 最後の経路は、足した経路そのものではなく、流れを分解して得る(逆辺で前の経路が付け替わるため)
- priority: 同じ長さのときの優先として、費用に小さな差を付ける等(未決)

## 実行時

計画(各機体の出発ターンと経路)を最初に作り、シミュレーション中はそれを読んで TurnResolver で確かめるだけ。
