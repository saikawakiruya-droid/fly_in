## パターンの作り方

- 評価シートの各項目を1つ以上のマップで確認できるようにし、1マップ=1つの観点に絞った。
- 期待結果は各マップの2行目以降のコメントに書いた(1行目は `nb_drones:` のまま。1行目コメントの扱いを P03 だけで試すため)。
- sim / edge の期待ターン数は手計算した最適値。多くても不正ではなく、先に制約違反がないことを見る。
- X11(25×25グリッド)は生成スクリプトで作った(スクリプト自体はリポジトリに入れていない)。

## 分かったこと

1. **配布マップ10枚すべてが現状のパーサーで読めない。** 1行目がコメントで、`tokenize_header` が物理1行目を
   `nb_drones:` と決め打ちしているため。`docs/bugs.md` 2026-10-16 に記録。
2. エラー系34パターンはすべて期待どおりの行番号・原因で `ParseError` になった(空ファイルだけ `line 0` 表示)。
3. 評価シートの「連結していないグラフ」はエラー処理とエッジケースの両方に出てくる。パーサーは受理する(X02〜X05 は
   パース成功)ので、経路探索側で「到達不能」を明確なエラーにする必要がある。現状はその処理がない。
4. ライブコーディング課題は `--capacity-info`(各ターンに「ゾーンX: Y/Zドローン、接続AB: Y/Z容量使用」を出す)。
   `cli.py` の `Args` と出力層に、フラグ1つと容量の集計を足しやすい形にしておくと10分に収まりやすい。

## 決定事項(2026-10-16、同日のうちにユーザーが判断)

- 「1行目」はファイルの物理的な1行目。`nb_drones:` でなければエラー(現行の動作を維持)。P03 は E35 としてエラー系に移した。
  上の「分かったこと」1 はバグではなく仕様となった。
- 到達不能の検出は、ゴールからの距離計算(ダイクストラ)のときに行う。X02, X03, X05 はパース成功 → 距離計算でエラー、が期待結果。
- 出力の検証スクリプトは今は作らない。
- 容量0について(質問への回答): `max_drones=0`(E12)、`max_link_capacity=0`(E15)とも現行パーサーは
  `must be a positive integer, got 0` の `ParseError` で拒否する。課題PDF VII.4「Capacity values must be positive integers」どおり。

## 残る未決事項

- メタデータキーの重複(`[color=a color=b]`)は現状後勝ちで受理する。エラーにするかはパターンに含めていない。
