# 最小構成版で削った機能のうち、レビュー(ピア評価)で役立つもの

日付: 2026-10-23
対象: `feature/minimal_build` / `feature/minimal_matplotlib`(develop から必須要件以外を削った試作)

観点: 評価者がその場で「ルールを守っているか」「結果が正しいか」を確かめやすいか。

## 戻す価値が高い(安くて効果が大きい)

| 機能 | レビューで効く理由 | コスト |
|---|---|---|
| ステップ実行(`--step`) | 容量・restricted の2ターンなどをターンごとに確かめられる。固定の待ち時間では大きなマップ(impossible_dream は44ターン)を追えない | 小 |
| 最後の要約行(ターン数・機数) | 課題の目標ターン数との比較がすぐできる。無いと `wc -l` で数えることになる | 数行 |
| BrokenPipe の特別扱い | `\| head` / `\| less` を途中で閉じると `internal error: BrokenPipeError` が出て、不具合に見える | 数行 |

## 検討の余地あり

- 通過中の接続を目立たせる(線を太く・色をはっきり): 今の色(`#96a0b9` と通常色 `#555c6c`)では見分けにくい
- `--delay`: ステップ実行があればほぼ不要
- ゾーンの占有数/容量の表示(負荷バーや `1/2`): 容量を超えていないことを示しやすい
- `--help` の説明文: 評価者は最初に `-h` を見ることが多い

## 削ったままでよい

- JSON 連携(`--parse-only` / `--from-world` / `--save-run`): 評価で使う場面が少なく、コード量は最大
- `--visual none`: `2>/dev/null` で代わりになる
- `FLYIN_DEBUG`: 開発用
- 軌跡・マウスを重ねたときの詳細: ステップ実行と通過中の色付けで代わりになる
- `PointGrid`: 配布マップの規模では影響なし

## 結論

戻すなら「ステップ実行・要約行・BrokenPipe」の3つ。次点は通過中の接続を目立たせること。
