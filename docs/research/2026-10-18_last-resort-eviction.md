# 調査記録: 立ち退きは「最後の手段」にする

- 日付: 2026-10-18
- 対象: `docs/research/2026-10-18_design-timed-reservation.md`(予約表と立ち退き)の Q-C
- 結論: **採用(ユーザー判断)**。各ドローンは、まず立ち退きを使わずに移動先の候補をすべて試し、どれも使えないときだけ立ち退きを試す。
- 方法: scratchpad の使い捨ての試作(コミットしていない)。完走したすべての出力を、試作とは別に書いた再生チェッカー
  (各ターンの最終負荷が容量以下、接続は出発のみ数えて容量以下、restricted へ出発した機は次のターンに必ず着く、隣のゾーンにしか動かない、
  最後に全機配達)で確かめ、違反は0件。

## 1. どんな規則か

ドローンが動く先を選ぶとき、候補は `Pathfinder.next_hops`(ゴールまで最短の一手。priority が先頭、あとは接続を宣言した順)に並んでいる。

- **最後の手段にしない場合**: 候補を先頭から1つずつ見る。restricted の候補で席がなければ、**その場で**在室機の立ち退きを試し、
  成功すればその候補へ出発する。
- **最後の手段にする場合(採用)**: 2回に分けて見る。
  1. 1回目: 立ち退きを使わずに、候補を先頭から見る。そのまま使える候補があれば、そこへ動く。
  2. 2回目: 1回目でどれも使えなかったときだけ、候補を先頭から見て、立ち退きを試す。

立ち退きの仕組み・規則そのものは変えない。「いつ立ち退きを使うか」だけを変える。

## 2. なぜ必要か

立ち退きは「本来は満員の候補を、空いていることにする」仕組みでもある。最後の手段にしないと、先頭の候補が満員でも立ち退きで使えてしまい、
**同じくらい短い、空いている別の候補があっても使われない**。その結果、出口の細い経路に機が集まり、全体が遅くなることがある。

### 例1(最小の例): 同じ長さの経路が2本あり、どちらも出口が細い

```text
nb_drones: 6
start_hub: s 0 0
hub: a 1 0 [zone=restricted max_drones=2]
hub: b 1 1 [zone=restricted max_drones=3]
end_hub: g 2 0
connection: s-a [max_link_capacity=2]
connection: a-g
connection: s-b
connection: b-g
```

- 経路は `s → a → g` と `s → b → g` の2本で、どちらも3ターン(restricted 2 + goal 1)。`next_hops(s)` は宣言順で `[a, b]`。
- `a-g` と `b-g` はどちらも接続容量1なので、それぞれの経路からは1ターンに1機しか goal へ出られない。
  6機を2本に3機ずつ分ければ5ターンで終わる。

| ターン | 今のプログラム(5) | 最後の手段にしない(6) | 最後の手段にする(5) |
|---|---|---|---|
| 1 | `D1-s-a D2-s-a D3-s-b` | `D1-s-a D2-s-a D3-s-b` | `D1-s-a D2-s-a D3-s-b` |
| 2 | `D1-a D2-a D3-b D4-s-b` | `D1-a D2-a D3-b D4-s-a D5-s-b` | `D1-a D2-a D3-b D4-s-b D5-s-a` |
| 3 | `D1-g D3-g D4-b D5-s-a D6-s-b` | `D1-g D3-g D4-a D5-b D6-s-a` | `D1-g D3-g D4-b D5-a D6-s-b` |
| 4 | `D2-g D4-g D5-a D6-b` | `D2-g D5-g D6-a` | `D2-g D4-g D6-b` |
| 5 | `D5-g D6-g` | `D4-g` | `D5-g D6-g` |
| 6 | | `D6-g` | |

何が起きているか(ターン2の D4):

- 先頭の候補 a には D1・D2 が着陸して残るので、ターン3の a は満員(容量2)。
- **最後の手段にしない**: D4 はその場で立ち退きを試す。D1 をターン3に g へ立ち退かせる予約ができる(g は end)ので、D4 は a へ出発する。
  b は空いていたのに使われない。D5 は b へ行くが、D6 も同じ理由で a に入り、a に D1・D2・D4・D6 の4機が集まる。
  a からは1ターンに1機しか出られないので、最後の D6 は6ターン目になる。
- **最後の手段にする**: D4 は1回目で b(そのまま空いている)を選ぶ。D5 は1回目でどれも使えず(a は満員、`s-b` は D4 が使用中)、
  2回目で a の立ち退きを使って a へ出発する。a と b に3機ずつ分かれ、5ターンで終わる。

### 例2: ランダムなマップでの例

ランダムに作ったマップ(6機。start から restricted の z0 と z3 を通る同じ長さの経路が2本あり、どちらも goal への出口の接続容量が1)でも、
同じ仕組みで「今5、最後の手段にしない6、最後の手段にする5」になった。悪化した6枚のうち5枚がこの型(先頭の候補に立ち退きで機が集まる)だった。

## 3. 効果(測定)

restricted を多めに含む小さなランダムなマップ(ゾーン3〜12、2〜15機、容量1〜3、接続容量1〜2)7,832枚と、配布マップ10枚・課題の例・revie_case で比べた。
ランダムなマップは restricted がかなり多い偏った集まりなので、割合は目安として読んでほしい。

| 項目 | 最後の手段にしない | 最後の手段にする |
|---|---|---|
| 接続上で詰まった | 0枚 | 0枚 |
| 今のプログラムより悪くなった | 6枚 | **1枚** |
| 今のプログラムより良くなった | 2,849枚 | 2,846枚 |
| 配布マップ10枚・課題の例・revie_case のターン数 | S07 4、circular_loop 10、the_impossible_dream 44 など | **すべて同じ** |
| X11(大きな格子)で作った立ち退きの数 | 76 | 19(ターン数は同じ71) |

### 残った1枚

12機のマップ。start から restricted の z0(容量1)へ行く経路と、z2(容量3)へ行く経路があり、どちらも次に restricted の z1 を通って goal へ出る
(z2 からは z8 を通る別の出口もある)。z1 から goal への接続容量は1。今のプログラムが11ターン、最後の手段にしても12ターン。

- ターン3で D8 が出発を考えたとき、z2 への接続はほかの機で埋まっていて、z0 はそのままでは満員だった。1回目ではどれも使えないので、
  2回目で z0 の在室機の立ち退きを使って z0 へ出発した。
- 今のプログラムでは D8 はここで1ターン待ち、次のターンに z2 へ出発して、z2 から空いている z8 の出口を使えた。
- 立ち退きを使って「今すぐ出発する」ほうが、「1ターン待って別の経路へ行く」より遅くなった例。どちらがよいかは、その先の経路の混み方
  (z1 の出口が細く、z0 からの機は必ず z1 を通る)で決まり、今の貪欲なスケジューラ(各機がそのターンにできる一番よい手を選ぶ方式)は
  そこまで見ていない。規則違反ではない。これを防ぐには経路全体の混み方の見積もりが要り、今回の範囲を超える。

## 4. 費用

- 判断のとき、候補を最大2回見るだけ。立ち退きの仕組み(予約表・再帰・取り消し)は変わらない。
- 実装は、候補を見るループを「立ち退きを使ってよいか」の印つきで2回回す程度の変更。
- テスト: 例1を「最後の手段にする/しない」で結果が変わる単体テストにできる。

## 5. 検討した代替案

| 案 | 内容 | 見送った理由 |
|---|---|---|
| 最後の手段にしない | 候補を先頭から見て、その場で立ち退きを試す(規則どおりの素直な形) | ランダムなマップで今より悪くなる例が6枚 |
| 空いている候補を優先する並べ替え | `next_hops` の順を、ターンごとに「空いている順」に並べ替える | 実質的に最後の手段と同じ効果で、priority を先頭にする決定(2026-10-16)との関係が分かりにくくなる |
| 経路全体の混み方を見積もる | 出口の通れる数などから、出発する経路を選ぶ | 残った1枚にも効く可能性はあるが、見積もりの規則が新しく大きく増える。今回は採らない |

## 6. README に書く場合の英語の文案

> **Eviction is a last resort.** When a drone chooses where to move, it first looks at every shortest next hop without evicting anyone.
> Only if none of them is usable does it try them again, this time allowing an occupant of a full restricted zone to be evicted
> (scheduled to move on) to make room. Otherwise a drone would pile onto the first listed route by evicting occupants, even when an
> equally short route was simply free, which can slow the whole run down. In our tests on 7,832 random maps this rule reduced the
> number of maps that got slower than the plain scheduler from 6 to 1, and it changed nothing on the provided maps.
